# 邮箱验证注册计划

本文是后续实现“注册邮箱验证码”的方案文档。当前代码状态是：注册不要求邮箱验证码，但企业成员邀请会通过 SMTP 发送邮件链接。

文档层级：`docs/README.md` -> 本文。本文是未来计划，不代表当前注册流程已经启用邮箱验证码。

## 1. 当前实现状态

### 已实现

- 注册字段：用户名、邮箱、密码、确认密码。
- 注册邮箱会转小写保存。
- 注册时会检查用户名和邮箱唯一性。
- 登录支持用户名或邮箱。
- 企业邀请成员时，会向成员邮箱发送邀请链接。
- 成员点击邀请链接并登录自己的账户后，可接受企业邀请。

### 未实现

- 注册前发送验证码。
- 注册时校验邮箱验证码。
- 验证码过期、重发、频率限制。
- 验证码错误次数限制。
- 邮箱验证状态字段。

## 2. SMTP 当前用途

SMTP 当前主要用于企业邀请邮件。

建议保留配置能力：

- SMTP Host。
- SMTP Port。
- SMTP Username。
- SMTP Password 或授权码。
- 发件人邮箱。
- 发件人名称。
- TLS/SSL 配置。

如果使用 QQ 邮箱：

- Host：`smtp.qq.com`
- SSL 端口：`465`
- STARTTLS 端口：`587`
- Username：完整 QQ 邮箱地址。
- Password：QQ 邮箱授权码，不是 QQ 登录密码。

## 3. 后续目标

注册时增加邮箱验证码流程：

1. 用户输入邮箱。
2. 前端点击“发送验证码”。
3. 后端生成 6 位数字验证码。
4. 后端发送验证码邮件。
5. 后端保存验证码哈希、过期时间、发送次数、错误次数。
6. 用户填写验证码、用户名、密码并提交注册。
7. 后端校验验证码后创建账户。
8. 验证码使用后立即失效。

## 4. 建议接口

### 发送注册验证码

```http
POST /api/user/register/email-code
```

请求：

```json
{
  "email": "user@example.com"
}
```

校验：

- 邮箱格式合法。
- 邮箱未被注册。
- 同一邮箱发送频率限制。
- 同一 IP 发送频率限制。

### 注册时校验验证码

```http
POST /api/user/register
```

请求增加字段：

```json
{
  "username": "user1",
  "email": "user@example.com",
  "password": "password",
  "password2": "password",
  "email_code": "123456"
}
```

校验：

- 验证码存在。
- 验证码未过期。
- 验证码未使用。
- 验证码匹配。
- 邮箱和验证码记录邮箱一致。

## 5. 建议数据表

可以新增 `email_verification_codes`：

| 字段 | 说明 |
| --- | --- |
| `id` | 主键 |
| `email` | 邮箱，统一小写 |
| `scene` | 场景，例如 `register` |
| `code_hash` | 验证码哈希，不保存明文 |
| `expires_at` | 过期时间 |
| `used_at` | 使用时间 |
| `send_count` | 发送次数 |
| `fail_count` | 校验失败次数 |
| `ip` | 请求 IP |
| `created_at` | 创建时间 |
| `updated_at` | 更新时间 |

兼容 SQLite、MySQL、PostgreSQL 时建议使用 GORM AutoMigrate，不写数据库专属字段类型。

## 6. 安全策略

- 验证码有效期建议 5 到 10 分钟。
- 同一邮箱 60 秒内不能重复发送。
- 同一邮箱每天限制发送次数。
- 同一 IP 每小时限制发送次数。
- 验证码校验失败超过 5 次后失效。
- 验证码保存哈希，不保存明文。
- 邮件内容不要包含密码或敏感 Token。

## 8. 与企业邀请的关系

邮箱验证码注册和企业邀请邮件是两套不同流程：

- 注册验证码用于确认邮箱所有权。
- 企业邀请邮件用于确认用户接受企业邀请。
- 两者可以复用 SMTP 配置，但不要复用同一 token 表。
- 企业邀请仍要求目标邮箱已注册；如果未来希望邀请未注册邮箱，需要新增“邀请后注册并自动加入企业”的流程。
