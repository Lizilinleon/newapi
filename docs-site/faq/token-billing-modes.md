# 令牌的按量优先/按次计费有什么区别？

ArmNet 字元服务 提供灵活的计费策略，以适应不同的业务需求。在创建令牌时，您可以选择计费模式。

## 计费模式详解[​](/faq/token-billing-modes#计费模式详解 "计费模式详解的直接链接")

### 1. 按量计费优先 (推荐)[​](/faq/token-billing-modes#1-按量计费优先-推荐 "1. 按量计费优先 (推荐)的直接链接")

**英文：** Pay-as-you-go First
这是最智能、最通用的模式。

- **机制：** 系统会自动判断用户请求的模型类型。
  - 如果请求的是**按量计费模型**（如 GPT-4, Claude 3 等文本模型），则按照 Token 数量扣费。
  - 如果请求的是**按次计费模型**（如 Midjourney, Suno 等无法计算 Token 的模型），则按照调用次数扣费。
- **优点：** **一个 Key 通吃全站模型**。无需担心模型类型，系统自动适配最优计费方式。

### 2. 仅按量计费[​](/faq/token-billing-modes#2-仅按量计费 "2. 仅按量计费的直接链接")

**英文：** Pay-as-you-go Only

- **机制：** 只允许调用支持 Token 计费的模型。如果尝试调用 Midjourney 等按次模型，会报错。
- **适用：** 纯文本处理业务，防止误调用昂贵的绘图模型。

### 3. 仅按次计费[​](/faq/token-billing-modes#3-仅按次计费 "3. 仅按次计费的直接链接")

**英文：** Pay-per-use Only

- **机制：** 无论什么模型，都尝试按次扣费。
- **注意：** 对于文本模型，这意味着哪怕只发了一个 "Hi"，也会扣除一次完整的对话费用（通常较贵），非常不划算。仅建议在特定老旧系统无法统计 Token 时使用。

### 4. 混合计费[​](/faq/token-billing-modes#4-混合计费 "4. 混合计费的直接链接")

**英文：** Hybrid
不推荐使用，容易造成账单混乱。

## 总结[​](/faq/token-billing-modes#总结 "总结的直接链接")

对于 99% 的用户，请直接选择 **"按量计费优先"**。它既能精确计算文本 Token 节省成本，又能无缝支持绘图和视频生成。
